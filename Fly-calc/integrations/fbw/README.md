# Вкладка Fly-calc в собственной сборке A32NX

Подготовлены **исходные патчи**, а не скомпилированный пакет самолёта. Они добавляют кнопку FC в ToolBar и React-маршрут `/fly-calc`. Расчётный сервис/SQLite/PDF работают на Windows, вне Coherent. Патчи не дают подтверждения работоспособности в кабине до полной сборки и проверки.

## Закреплённые исходники

| Версия MSFS | Ветка FlyByWire | Commit | Патч |
|---|---|---|---|
| 2020 | fs2020-master | `672384b9602a84d6832b8852cd6ec0abdd006f85` | `patches/msfs2020.patch` |
| 2024 | master | `255546cb02db1c7b40d2505ac621a9d36748d258` | `patches/msfs2024.patch` |

Источники: [репозиторий](https://github.com/flybywiresim/aircraft), [объявление раздельных выпусков](https://flybywiresim.com/notams/development-update-sim-specific-releases-for-msfs-2020-and-2024/). SHA-256 исходных файлов и патчей — `lock.json`. Генератор — `python scripts/generate_fbw_patches.py` из корня Fly-calc; после изменения общего интерфейса патчи нужно пересоздать.

## Полная сборка: ещё не выполнена

Нужны Git, Docker Desktop с поддержкой Linux containers, полный checkout и submodule large-files. Выполняйте сборку в **отдельном** checkout для каждой версии. Для MSFS 2024 пример из папки Fly-calc:

```powershell
git clone --branch master https://github.com/flybywiresim/aircraft.git vendor/fbw-2024
git -C vendor/fbw-2024 checkout 255546cb02db1c7b40d2505ac621a9d36748d258
git -C vendor/fbw-2024 submodule update --init
node scripts/apply_fbw.mjs msfs2024 vendor/fbw-2024 --check
node scripts/apply_fbw.mjs msfs2024 vendor/fbw-2024 --apply
```

Затем из `vendor/fbw-2024`:

```powershell
$env:FBW_TYPECHECK = '1'
scripts\dev-env\run.cmd ./scripts/setup.sh
scripts\dev-env\run.cmd ./scripts/build.sh -r "a32nx"
```

Для MSFS 2020 используйте ветку `fs2020-master`, каталог `vendor/fbw-2020`, соответствующий SHA и параметр `msfs2020`. У закреплённых ревизий используется `scripts/build.sh`; старый предполагаемый `build_a32nx.sh` не найден и не используется. Полный Docker build с **FBW_TYPECHECK=1**, upstream lint и проверка EFB обязательны перед установкой.

Скрипт `apply_fbw.mjs` откажет при неправильном HEAD и сначала выполнит `git apply --check`. Он не переключает ветку, не сбрасывает локальные изменения и не делает force-apply. В текущей среде проверена только применимость к двум реальным исходным файлам каждого снимка; полноценные зависимости и крупные ассеты не скачивались.

Патч касается общей EFB-папки: сборка A380 из такого checkout тоже может увидеть маршрут. Для этого этапа собирается только A32NX. Закрытые/сгенерированные WASM и модель самолёта не изменяются.

## Установка и восстановление

1. Завершить MSFS, определить **реальный Community path** в настройках/`UserCfg.opt` нужной версии. Не использовать угаданный каталог.
2. Сохранить штатный A32NX и его версию в резервной папке **за пределами Community**. Сохранить пользовательские настройки отдельно. Не держать одновременно штатный и собственный пакеты с одинаковым идентификатором.
3. Установить пакет A32NX из фактического `out` выбранной сборки только после успешных проверок build/typecheck/lint. Состав и выходной путь сверить с инструкциями закреплённой ревизии; исходный `.patch` нельзя копировать в Community как самолёт.
4. Запустить локальный Fly-calc, затем MSFS; проверить FC → Fly-calc. Протокол — `docs/validation-plan.md`.
5. Для восстановления завершить симулятор, убрать собственный пакет из Community в отдельный каталог, вернуть проверенный штатный пакет либо переустановить ту же версию через FlyByWire Installer. Запустить штатный EFB и проверить основные функции.

Никаких изменений установленного самолёта здесь не выполнялось. Пакет не публикуется в официальный FlyByWire Installer.

## Обновления

Обновление FlyByWire не считается совместимым автоматически. Сначала сохранить новую ревизию, прочитать её инструкции и настройки EFB, заново создать патч с проверкой якорей, сверить исходные хэши, выполнить typecheck/lint/build и полный сценарий для **обеих** версий MSFS. Не применять старый патч на новый HEAD с обходом проверки. Поддержка обновления фиксируется новым lock-файлом и отдельным результатом проверки.

## Сеть и документы

Fly-calc слушает только `127.0.0.1:8147`. Клиент использует XHR с таймаутом и повторным подключением. Для прототипа разрешены local HTTP origin, `coui://html_ui` и `null`; фактический origin Coherent и правила доступа к localhost нужно проверить в обоих симуляторах. Windows Firewall/LAN-открытие порта не требуется и не настраивалось.

PDF загружается в Windows-интерфейсе и преобразуется в PNG локально. flyPad получает список документов и отдельные изображения страниц. Открытие PDF внешней ссылкой и `<input type=file>` в Coherent не считаются подтверждёнными; просмотр PNG проверен только в браузере. Порт не подменяет SimBridge или штатные сервисы самолёта.
