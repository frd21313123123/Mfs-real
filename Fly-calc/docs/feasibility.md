# Fly-calc: отчёт о реализуемости

Дата проверки: **09.10.2026**. Область: бесплатное личное использование в MSFS и X-Plane, Windows-приложение и собственная вкладка flyPad A32NX; дополнительно — отображение в планшете Fenix.

## Решение по первому этапу

**Бесплатная полная мировая навигационная база не подтверждена.** Найдены разрешённый мировой справочник аэропортов, старый набор точек/радиосредств/трасс и официальный региональный набор процедур FAA. Ни один проверенный источник и ни одна проверенная комбинация не закрывают мировые SID, STAR, заходы, все ограничения направлений и совместимые связи с ВПП.

Условия начала полноценной разработки расчёта из согласованного плана пока не выполнены. Поэтому сервер не строит приблизительный маршрут, не назначает запасной и не выдаёт выдуманные топливо/время. Этап даёт исследование, проверяемые исходные патчи, локальный API и интерфейс для дальнейших технических проверок.

Полная сборка A32NX и проверки в MSFS 2020/2024 **не выполнены**. На этом компьютере нет команды Docker; симуляторы и Fenix не обнаружены в проверенных стандартных каталогах. Поиск не был полным сканированием всех дисков. Это ограничение среды, а не доказательство несовместимости.

Исследование национальных публикаций не было исчерпывающим обзором всех государств. Публичный PDF для конкретного аэропорта не подтверждает наличие свободной глобальной базы. Неофициальные копии платных циклов, аддонные навданные с неизвестными правами и архивы без лицензии не рассматриваются как решение.

FlightGear закреплён на `b7b6071beac21f604dcc65d3aad276c07a378b0d`. Старый `ReadMe.FG226.txt` в репозитории не заменяет заголовки циклов непосредственно в файлах. GPL репозитория не использована как единственное доказательство лицензии данных.

В интерфейсе показываются обозначение 2013.10 и примерный возраст в годах от 2013 года. Точная effective date этого старого набора не установлена; возраст не выдаётся как точное число дней. Для OurAirports показывается дата локального получения снимка, не AIRAC.

## Измеренное покрытие всего снимка

Полный машинный результат — `evidence/coverage.json`; повторение — `python scripts/audit_data.py`. Число записей не равно числу всех существующих аэропортов или процедур. Авторитетного полного мирового знаменателя в проверенных источниках нет, поэтому процент глобальной полноты **не рассчитан**.

| Набор | Измерено |
|---|---:|
| OurAirports, все записи, включая закрытые и вертодромы | 86 226 |
| Действующие записи с уникальным четырёхбуквенным ICAO | 10 531 |
| Коды стран/территорий во всём OurAirports | 247 |
| Записи ВПП / радиосредств OurAirports | 48 330 / 11 008 |
| ВПП без родительского airport_ident | 0 |
| Действующие ICAO-аэропорты без записей ВПП | 2 170 |
| FlightGear, записи fixes / навигационные записи | 119 720 / 26 771 |
| Сегменты трасс / отдельные имена трасс после разделения составного поля | 70 285 / 7 344 |
| Fix-идентификаторы, встречающиеся больше одного раза | 3 624 |
| Сегменты, не связавшиеся со справочником по строгому ключу | 16 528 |
| Диапазоны высоты трасс с нижней границей выше верхней | 0 |
| FAA CIFP 2609, строки / PA-аэропорты / записи ВПП | 396 816 / 13 307 / 16 879 |
| FAA, уникальные имена SID / STAR / заходов в области аэропорт+регион | 2 190 / 1 916 / 10 232 |

Навигационные записи FlightGear включают компоненты ILS и другие типы; 26 771 нельзя трактовать как число уникальных радиомаяков. Составное поле трассы может содержать несколько имён через дефис: 9 200 значений поля соответствуют 7 344 отдельным именам, а не 9 200 независимым трассам.

Строгий ключ FlightGear — `(ident, latitude rounded to 4 decimals, longitude rounded to 4 decimals)`, с совместным поиском в fixes и nav. 16 528 несопоставленных сегментов — **результат этого алгоритма**, а не установленное число ошибок источника: нужны анализ точности координат, типов радиосредств, встроенных маршрутных точек и вариантов записей. Коллизии не разрешаются одним только именем. База маршрутизации из этих записей не создана.

### Географическая выборка

Окно — ±2° широты и долготы вокруг аэропорта. Числа ниже проверяют наличие данных рядом с выбранной точкой; они не доказывают связность маршрута или полноту региона.

| Регион | ICAO | ВПП OurAirports | Точки FG в окне | Сегменты FG с концом в окне | Аэропорт в FAA 2609 |
|---|---|---:|---:|---:|---|
| Европа | EGLL | 2 | 1 070 | 571 | Нет |
| Россия | UUEE | 3 | 276 | 176 | Нет |
| Северная Америка | KJFK | 4 | 3 162 | 786 | Да |
| Азия | RJTT | 4 | 368 | 322 | Нет |
| Африка | FAOR | 2 | 158 | 132 | Нет |
| Южная Америка | SBGR | 2 | 109 | 134 | Нет |
| Океания | YSSY | 3 | 388 | 180 | Нет |

FAA содержит записи нескольких area codes, включая CAN/PAC; это не мировой набор. Readme **самого архива 2609** прямо исключает non-US airways и говорит, что ATS routes не содержат directional restrictions. PA-коды могут быть FAA identifiers, когда ICAO отсутствует; 13 307 нельзя сравнивать напрямую с 10 531 четырёхбуквенными ICAO.

Упрощённая проверка явных `RWxx` transitions FAA нашла 1 219 пар airport+RW и четыре несопоставления: 1K4 RW17/RW35, KORF RW14/RW32. Это неполная проверка: суффиксы ВПП, all-runway transitions, approach coding, continuation records и ARINC leg semantics полностью не декодировались. Эти четыре пары помещаются в список для исследования, а не объявляются подтверждёнными ошибками FAA.

Архив `CIFP_261001.zip` пришёл усечённым и был отвергнут: нет корректной центральной директории ZIP. Проверенный fallback `CIFP_260903.zip` прошёл CRC, readme задаёт действие **03.09.2026 0901Z–01.10.2026 0901Z**. Он устарел на дату проверки. Текущий readme по общему URL уже относится к другому выпуску и не использован для присвоения архиву цикла. Последние четыре символа ARINC-записи — цикл её последнего изменения; распределение этих значений не доказывает смешение циклов внутри официального файла.

## Совместимость и расчётный движок

Снимок OurAirports не имеет AIRAC, FlightGear — 2013.10, FAA — 2609. Текущее имя/координаты/номер ВПП нельзя молча присоединять к старой процедуре. Нужны независимые версии наборов, происхождение каждой записи, scoped-ключи аэропорт/регион/тип/идентификатор и проверка координат. Для изменения обозначений ВПП требуется явное подтверждение; автоматическая подстановка ближайшей ВПП недопустима.

Для будущего графа нужны направленные рёбра трасс и процедур с вертикальными ограничениями, условиями оборудования RNAV/RNP/радиосредств, последовательностями переходов, RF/hold/discontinuity и правилами выбора ВПП/захода. Неизвестное ограничение не трактуется как отсутствие ограничения. Сам факт совпадения конечной точки STAR с точкой захода не означает разрешённую связь.

[EUROCONTROL RAD](https://www.public.nm.eurocontrol.int/RAD/), NOTAM и временные закрытия пока не проверяются. Перед настоящим расчётом потребуется отдельное решение, какие опубликованные ограничения доступны и как их версия привязывается к плану. В этом прототипе ответ содержит `RAD_NOTAM_NOT_CHECKED`; расчёт полёта закрыт полностью. ETOPS, V-speeds, MCDU uplink и подача плана диспетчерам остаются вне этапа.

Запасной должен проверяться по совместимым процедурам, оборудованию, геометрии/характеристикам ВПП, достижимости и топливу ухода/полёта/ожидания; метеоминимумы требуют отдельного источника и правил. Ближайший аэропорт по расстоянию не считается рассчитанным запасным. Чарты — документы для просмотра, а не подмена машинной базы процедур.

## flyPad A32NX

FlyByWire публикует [раздельные версии для MSFS 2020 и 2024](https://flybywiresim.com/notams/development-update-sim-specific-releases-for-msfs-2020-and-2024/). Закреплены:

| Симулятор | Ветка | Commit |
|---|---|---|
| MSFS 2020 | fs2020-master | `672384b9602a84d6832b8852cd6ec0abdd006f85` |
| MSFS 2024 | master | `255546cb02db1c7b40d2505ac621a9d36748d258` |

У обеих ревизий страницы зарегистрированы React-маршрутами в `fbw-common/src/systems/instruments/src/EFB/Efb.tsx`. Подготовлены патчи кнопки FC и маршрута `/fly-calc` с общим компонентом FlyCalc. Добавление идёт в существующий React EFB, не в новый FSComponent-инструмент. Клиент использует XHR, ES2017 и API `http://127.0.0.1:8147/api/v1`; Node/Python остаются только в Windows-сервисе.

`git apply --check` выполнен на скачанных исходных файлах обоих закреплённых снимков. Общий компонент прошёл отдельный строгий TypeScript и браузерный тест. Upstream typecheck/lint, Docker build, установка Community, Coherent runtime и оба симулятора **не проверены**. Поэтому патчи — исходный технический прототип, не готовый самолётный пакет. Инструкции восстановления и перепроверки обновлений — `integrations/fbw/README.md`.

PDF преобразуется локальным Python/PDFium в PNG; интерфейс не требует встроенного PDF-плагина Coherent. PDF генерация, загрузка и изображения подтверждены в API/Edge. Доступность XHR/CORS, `null` origin, PNG и выбора файла внутри flyPad требует проверки в обеих версиях симулятора. В Windows пользователь выбирает PDF; в планшете предполагается открытие уже загруженных страниц.

## Что препятствует полноценному выпуску

1. Нет подтверждённого бесплатного мирового источника процедур с правами на автоматическую загрузку и производный граф.
2. Не решены межцикловые ключи, пропуски, направления трасс, полная ARINC-семантика и связи ВПП/процедур.
3. Требуется полный FBW checkout с large-files, Docker build, установка и фактические проверки MSFS 2020/2024.
4. Для нативного планшета Fenix требуется поддерживаемый способ расширения и проверка точной версии.
5. Для каждого аддона нужны разрешённые данные/собственные измерения и независимый допуск до 5%.

Следующий шаг после появления полного разрешённого источника — нормализация и проверка данных, затем граф с ограничениями, расчёт фаз и запасного, OFP и PDF. До снятия первого препятствия можно завершать технические проверки интерфейса в установленном симуляторе, но нельзя выдавать исследовательский набор за полную мировую маршрутизацию.
